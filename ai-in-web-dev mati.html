02 / the new build sequence

From a sentence to a shipped page.

The order hasn't changed much — design, build, test, ship — but AI now sits inside every step instead of waiting at the edges.

STEP 01

Describe

A rough brief, a sketch, or a competitor link goes in — AI turns it into a structured layout and component list.

STEP 02

Generate

Components, styles and data-fetching logic get scaffolded in seconds, matching the project's existing patterns.

STEP 03

Review

A developer reads the diff, not the docs — approving, editing, or rejecting what the model proposed.

STEP 04

Ship

AI writes the commit message, flags the regressions, and drafts the release notes before the PR merges.

03 / the workflow, as a diff

What actually changed isn't the code. It's the timeline.

Same outcome, different route. Here's a typical feature request, before and after.

feature/pricing-page — workflow.diff
−Wireframe in a design tool, wait two days for review
−Hand-code layout, breakpoints, and states from scratch
−Write unit tests after the feature is "done"
−Manually check contrast ratios and tab order
+Describe the section, get three layout options in minutes
+Generate the component tree, then hand-tune spacing and taste
+Tests are drafted alongside the component, not after it
+Accessibility issues get flagged inline, before the PR opens
04 / the honest part

What AI still hands back to you.

Generation is the easy 80%. The remaining 20% is still where the job lives.

?

Judgment calls

Which trade-off to make when speed, cost, and user experience pull in different directions — that's still a human decision.

△

System architecture

AI is strong inside a file. It's weaker at deciding how forty files should relate to each other two years from now.

✓

Taste

It can generate ten versions of a hero section. Knowing which one actually fits the brand is still a design skill, not a prompt.
